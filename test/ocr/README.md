# OCR 실습 — 이미지 속 글자 읽기

OCR(Optical Character Recognition)은 **이미지 속 글자를 텍스트 데이터로 바꾸는 기술**입니다.
로봇이 라벨·표지판·계기판을 읽거나, 문서를 디지털화할 때 써요.
이 실습은 한국어를 지원하는 **EasyOCR**을 사용해요.

## 동작 원리 — 두 단계

```
이미지 ──▶ ① 글자 검출 ──▶ 글자 영역 박스 ──▶ ② 글자 인식 ──▶ "유통기한 2026.12.31"
            CRAFT                               CRNN
          "어디에 있나?"                       "무슨 글자인가?"
```

| 단계 | 모델 | 하는 일 |
|---|---|---|
| ① 검출 | **CRAFT** | 픽셀마다 "글자 중심일 확률"과 "글자 사이 연결부일 확률"을 히트맵으로 예측하고, 이를 이어 단어·줄 박스를 만들어요 |
| ② 인식 | **CRNN** | 잘라낸 영역을 CNN으로 특징 추출 → BiLSTM으로 왼쪽→오른쪽 순서대로 읽기 → **CTC 디코딩**으로 `안안녕--`을 `안녕`으로 정리해요 |

- 검출이 놓친 글자는 인식도 절대 못 해요. 그래서 OCR 정확도는 **검출 품질**에 크게 좌우돼요.
- 인식 모델은 언어마다 따로 있어요. `['ko', 'en']`이면 한국어+영어 모델을 써요.

> YOLOE와 비교하면 ① 검출이 "어디에", ② 인식이 "무엇"에 해당해요.
> YOLO는 이 둘을 한 번에 하지만, OCR은 보통 두 모델을 이어 붙여요.

## 폴더 구성

| 파일 | 설명 |
|---|---|
| `ocr_practice.py` | 실습 코드 (주석에 원리 설명) |
| `label.jpg` | 코드가 직접 만드는 제품 라벨 이미지. **정답을 알고 있어서** 오인식을 바로 확인할 수 있어요 |
| `korean_sign.png` | 실제 도로 표지판 사진 (EasyOCR 공식 예제) |
| `runs/` | 결과 이미지 |

EasyOCR 모델(검출 + 한국어/영어 인식, 약 100MB)은 이 폴더가 아니라 `C:\Users\작업용\.EasyOCR`에 저장돼요.

## 설치

```powershell
py -m pip install easyocr
```

> ⚠️ EasyOCR을 설치하면 `opencv-python-headless`가 같이 깔려요. 이게 기존 OpenCV를 덮어써서 **창 띄우기 기능이 꺼져요** (SAM2 click 모드가 동작하지 않게 돼요).
> 설치 후 아래 명령으로 원래대로 돌려주세요.
>
> ```powershell
> py -m pip uninstall -y opencv-python-headless
> py -m pip install --force-reinstall --no-deps opencv-python
> ```

## 실행

`test` 폴더에서:

```powershell
py ocr\ocr_practice.py --mode basic      # 글자 읽고 박스 그리기
py ocr\ocr_practice.py --mode pipeline   # 검출 → 인식을 따로 실행
py ocr\ocr_practice.py --mode robust     # 흐림·저해상도·회전 등에 얼마나 강한가
py ocr\ocr_practice.py --mode find       # 특정 단어 찾기 + 값 뽑기
py ocr\ocr_practice.py --mode all        # 전부
```

### 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--mode` | `all` | `basic` / `pipeline` / `robust` / `find` / `all` |
| `--source` | 예제 이미지 2장 | 이미지 경로 (여러 개 가능) |
| `--langs` | `ko en` | 인식 언어 (예: `en`, `ja en`). `ko`와 `ja`처럼 함께 쓸 수 없는 조합도 있어요 |
| `--find` | `유통기한` | `find` 모드에서 찾을 단어 |
| `--min-conf` | `0.3` | 이 신뢰도보다 낮은 결과는 제외 |
| `--gpu` | 꺼짐 | CUDA GPU가 있을 때 켜면 훨씬 빨라요 |

### 예시

```powershell
# 송장번호를 찾아서 번호만 뽑기
py ocr\ocr_practice.py --mode find --find 송장번호

# 내 사진 읽기 (영수증, 과자 봉지, 책 표지 등)
py ocr\ocr_practice.py --mode basic --source "C:\Users\작업용\Pictures\receipt.jpg"

# 영어만 인식
py ocr\ocr_practice.py --mode basic --langs en
```

## 모드별 상세와 실제 결과

### 1. basic — 글자 읽기

`label.jpg` 결과 (정답과 비교):

| 신뢰도 | 인식 결과 | 정답 | |
|---|---|---|---|
| 0.97 | PHYSICAL **Al** LAB | PHYSICAL **AI** LAB | ❌ 대문자 I를 소문자 l로 |
| 0.56 | 제품명: 로봇 그리퍼 부품 A-17 | 같음 | ✅ |
| 0.77 | 유통기한 2026.12.**37** | 2026.12.**31** | ❌ 1을 7로 |
| 0.51 | 송장번호 1234-5678-9012 | 같음 | ✅ |
| 0.98 | 주의: 뜨거움 HOT | 같음 | ✅ |
| 0.53 | 작은 글씨는 인식이 어려**올** 수 있습니다 | 어려**울** | ❌ 작은 글씨 |

`korean_sign.png` 결과: 서울 / 평 양 / Seoul / Pyeongyang / 56Km / **2O5Km**(숫자 0을 알파벳 O로)

- 결과는 `(박스 네 꼭짓점, 텍스트, 신뢰도)` 형태예요. 기울어진 글자도 표현하려고 사각형 대신 **사각 다각형**을 써요.
- 결과 이미지의 박스 색: 신뢰도가 높을수록 초록, 낮을수록 빨강이에요.
- 흩어진 결과를 **읽는 순서(위→아래, 왼→오른쪽)**로 정렬해서 전체 텍스트도 보여줘요.

### 2. pipeline — 두 단계를 나눠 보기

```python
horizontal_list, free_list = reader.detect(img)            # ① 검출: 박스만
results = reader.recognize(img, horizontal_list[0], free_list[0])  # ② 인식: 글자
```

- `label.jpg` 기준: ① 검출 3.3초(박스 7개) → ② 인식 1.1초. **검출이 더 무거워요.**
- `runs/pipeline_1_detect.jpg`에는 박스만 있고, `pipeline_2_recognize.jpg`에는 글자까지 있어요.

### 3. robust — 이미지 품질에 따른 변화

| 변형 | 상황 | 검출 수 | 평균 신뢰도 | 결과 |
|---|---|---|---|---|
| original | 원본 | 7 | 0.73 | 기준 |
| blur | 초점 흐림 | 8 | 0.50 | 그리퍼→그리**피**, 송장→**승**장 |
| low_res_30% | 멀리서 찍음 | 7 | 0.38 | 유통기한→**유물기하** |
| rotate_15deg | 살짝 기울어짐 | 27 | **0.87** | ⚠️ 신뢰도는 높은데 글자가 **조각조각** |
| rotate_90deg | 옆으로 누움 | 18 | 0.30 | 거의 실패 |
| ↳ + `rotation_info` | 회전 보정 | 18 | 0.80 | 일부 복구 (`1234-5678-9012`) |
| low_contrast | 흐린 인쇄·역광 | 7 | 0.69 | 비교적 잘 버팀 |
| noise | 어두운 곳 | 7 | 0.72 | 비교적 잘 버팀 |

- **해상도와 회전**이 가장 치명적이에요. 카메라를 설치한다면 글자가 충분히 크고 똑바로 보이게 해야 해요.
- **신뢰도가 높다고 정답은 아니에요.** 신뢰도는 "이 조각을 이 글자로 읽은 확신"일 뿐이에요.
- `runs/robust_grid.jpg`에서 변형별 결과를 한 장으로 비교할 수 있어요.

### 4. find — 단어 찾고 값 뽑기

```
'유통기한 2026.12.37' (신뢰도 0.77) 중심 좌표 (234, 235)
  값 후보: '2026.12.37'  → 후처리: '2026.12.37'
```

- 키워드와 값이 한 박스로 묶여 나오는 경우가 많아서, **키워드 뒤 부분을 값**으로 뽑아요.
- `fix_digits()` 후처리는 숫자 옆에서 헷갈리기 쉬운 글자를 숫자로 고쳐요 (`O→0`, `I/l→1`, `S→5`, `B→8`).
  - `2O5Km` → `205Km` ✅
  - `2026.12.37`처럼 **숫자끼리 틀린 건 못 고쳐요.** 날짜 형식 검사(월 1~12, 일 1~31) 같은 도메인 지식 검증이 필요해요.
- 로봇 응용 예: 유통기한 읽기, 택배 송장번호 찾기, 버튼 라벨 찾기

## 자주 겪는 문제

| 증상 | 해결 |
|---|---|
| `No module named 'easyocr'` | `py -m pip install easyocr` (설치 후 위의 OpenCV 복구도 꼭 하기) |
| SAM2 click 창이 안 뜸 | EasyOCR 설치로 OpenCV가 바뀐 것이에요. 위 **설치** 항목의 복구 명령을 실행하세요 |
| `파일을 찾을 수 없습니다` | 경로는 명령을 실행한 위치 기준이에요. 전체 경로를 쓰세요 |
| 작은 글씨를 못 읽음 | 사진을 더 가까이서 찍거나 고해상도로 찍으세요 |
| 기울어진 사진을 못 읽음 | 코드의 `rotation_info=[90, 180, 270]` 옵션을 참고하세요 (대신 느려져요) |
| 느림 | CPU에서는 정상이에요(이미지 한 장에 2~5초). GPU가 있으면 `--gpu` |

## 실습 과제

1. basic 결과에서 작은 글씨(size 22) 줄의 정확도를 큰 글씨와 비교해보자.
2. `--langs en`으로만 돌리면 한국어는 어떻게 나올까?
3. robust에서 가장 치명적인 변형은 무엇인가? 카메라를 설치한다면 무엇을 조심해야 할까?
4. 휴대폰으로 과자 봉지, 영수증, 책 표지를 찍어 `--source`로 넣어보자.
5. find 모드로 `유통기한` 값을 뽑은 뒤, 날짜 형식이 올바른지 검사하는 함수를 직접 만들어보자.
